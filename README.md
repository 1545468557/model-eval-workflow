<h1 align="center">模型评测全流程 Skill</h1>


> 7步流程带你从"定目标"到"出报告"，系统化完成大模型选型、产品迭代效果验证、Agent能力评估等评测任务。

---

## ✨ 这个 Skill 能帮你做什么？

当你需要回答以下问题时，这个 Skill 就是你的标准化工具箱：

- **"这几个大模型，我该选哪个？"** → 系统化选型评测
- **"新版本比旧版本效果好吗？"** → 产品迭代效果验证
- **"这个 Agent 真的能解决用户问题吗？"** → 能力评估与验收
- **"怎么证明模型优化有效？"** → 数据驱动的效果论证

**核心理念：先定目标再评测，不设加权总分，Bad Case 必须有优化建议。**

---

## 📋 7步标准流程

| 步骤 | 名称 | 核心产出 | 关键原则 |
|------|------|---------|---------|
| 第1步 | 定目标 | 评测目标卡 | 一句话说清通过标准 |
| 第2步 | 定维度 | 核心指标+一票否决项 | 2-3个可量化指标 |
| 第3步 | 设计评测集 | 按场景设计测试题（附30条CSV示例） | 常规50%+复杂25%+边界15%+对抗10% |
| 第4步 | 定打分标准 | 可执行的评分规则 | 二值判断优先，档位有锚点 |
| 第5步 | 试标对齐 | 按风险定义校准门槛的锁定标准 | 跳过这步=全部返工 |
| 第6步 | 批量评测 | 结果汇总表 | 控制变量，费用监控 |
| 第7步 | 输出评测报告 | 结论先行的完整报告 | Bad Case必须有优化建议 |

## 💡 核心原则与避坑指南

### 三大核心理念

1. **先定目标再评测**：没有明确目标的评测都是浪费
2. **不设加权总分**：核心指标独立必过，一票否决直接淘汰
3. **Bad Case 必须有优化建议**：只列问题不解决，评测就没有价值

### 七个常见坑

| 坑 | 后果 | 避坑方法 |
|----|------|---------|
| 目标不明确 | 评测完不知道选谁 | 先写评测目标卡，一句话说清通过标准 |
| 维度太多 | 什么都想测=什么都测不准 | 只留2-3个核心指标+1个一票否决 |
| 用1~5分打有明确门槛的指标 | 一致率低，模糊通过条件 | 二值判断+数量汇总，质量层次留给GSB |
| 跳过试标对齐 | 批量评测结果不可用，全部返工 | 一致率>80%才批量，<80%改标准 |
| 不控制变量 | 结果不可比，不知道是模型还是流程的差异 | 除了模型，其他全部相同 |
| 首轮就跑30条 | 成本高，模型不行就白跑 | 首轮只用1条核心用例筛选，达标者再复测 |
| Bad Case只列问题 | 评测完不知道怎么优化 | 每个Bad Case必须有根因分析+优化建议 |

## 📊 三种打分方式对比

| 方式 | 适用场景 | 优点 | 缺点 |
|------|---------|------|------|
| **二值判断** | 有明确通过/不通过门槛 | 一致率高，不需要大量case | 不能区分合格者的质量层次 |
| **GSB对比法** | 合格模型之间的相对比较 | 不需要绝对标准，直接对比 | 只能相对排名，不能判断是否达标 |
| **1~5分评分法** | 质量层次丰富、没有明确门槛 | 能区分细微差异 | 一致率低，需要大量case校准 |

**推荐组合**：核心指标用二值判断 + 达标模型之间用GSB补充盲比
